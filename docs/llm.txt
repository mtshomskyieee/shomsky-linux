POSTURE

- Original source is MIT, provided AS IS. Operators run the container at their own risk. Do not invent a second license or warranty for that code.
- Agent mode can run real commands and write files inside the container and its bind mounts. Hallucination mode and operator hardening (non-root user, read-only rootfs, allow_root_mode = false) reduce exposure. They do not move responsibility off the operator.
- AI-assisted contributions are expected. Before editing code, load docs/adr/README.md and every Accepted ADR that touches the change. Follow those decisions.
- A pull request that knowingly violates an Accepted ADR must include a superseding ADR, or a Status change, in the same change set.
- The human submitter remains responsible for correctness, security impact, and license compliance.
- Brand as "Shomsky Linux, based on Alpine Linux." The project is not affiliated with the Alpine Linux project. Do not treat Alpine marks as ours. Inventory: docs/licensing.md.


PRODUCT

Shomsky Linux is an Alpine-derived container distribution. Its linux shell is the Rust binary engram-shell. The container is the sandbox. Inference is local mistral.rs on 127.0.0.1:1234, speaking OpenAI-compatible HTTP. Weights are downloaded once into a volume. They are not in the image or the git tree. The shell executes tools. The model proposes them and cannot escalate its own mode.

Architecture: docs/adr/0001-alpine-llm-linux-shell.md

    entrypoint.sh
      resolve SHOMSKY_MODEL -> /etc/engram/models.toml
      download GGUF -> /engram/models
      mistralrs serve --format gguf --cpu 127.0.0.1:1234
      shomagentd
      exec engram-shell
        BusyBox ash           real tools (agent / root)
        /engram/skills        markdown manuals
        stdio MCP children    engram-cmdfreq and others (no ports)


CONSTRAINTS THAT NEED A SUPERSEDING ADR TO CHANGE

State these as facts when you design a change. Do not route around them.

- Flagship image is Alpine/musl. CUDA has no musl path. containers/Dockerfile.cuda is a separate glibc companion, not the flagship. (ADR-0001)
- Default inference is in-container mistral.rs. No first-party cloud Anthropic, OpenAI, or Ollama client as the product path. An alternate OpenAI-compatible URL is an operator extension. (ADR-0003)
- GGUF weights stay out of the image and the git tree. (ADR-0003, docs/licensing.md)
- Real execution is BusyBox ash. Mode policy stays in the shell. Unknown tool names are ignored, not executed. (ADR-0001)
- Extra tools are local stdio MCP children. Config has command, args, and env, and no url. A command containing :// is refused. No TCP/UDP listen. Compose does not publish MCP ports. (ADR-0004)
- Hallucination mode: real tools and MCP calls are quiet no-ops. No disk writes. (ADR-0001, ADR-0004)
- Learn installs under $HOME/bin only after BATS passes. /usr/local/bin is shomsky publish only. (ADR-0008)
- shomagent members exist only after an explicit attach. read cannot write. Findings share /run/shomagent/notify. Supervision is in-process, not s6/runit. (ADR-0007)
- First-party CI is GitHub Actions. Default ci builds the image and runs the non-LLM suite. LLM smoke is opt-in (RUN_LLM_SMOKE, tests-llm, RUN_LLM_TESTS=1) with SHOMSKY_MODEL=tiny. Do not publish images from every PR. Releases are tag-driven to ghcr.io/mtshomskyieee/shomsky-linux. (ADR-0005)
- Rust edition 2021, rust-version 1.74. Release profile optimizes for size (LTO, opt-level z, strip). Prefer MIT or Apache-2.0 dependencies. (ADR-0002)

MODES

docs/shell-modes.md
Switch with :mode agent, :mode hallucination, or :mode root, or use :menu. The model cannot switch itself.

- agent (default). Real tools. Shell-shaped lines (ls, pipelines, redirects) run immediately via BusyBox and do not wait on the model. Natural language goes to the model. cd persists. cd ~ is /engram/user.
- hallucination. In-memory filesystem for common builtins. Other lines go to the model with no tool schemas. Nothing touches the real disk. Sessions save under the history directory. Offer resume or fresh on entry.
- root. Every line is BusyBox. No LLM. Gated by allow_root_mode (default true). cd ~ is /root.

Interactive commands listed in engram/skills/ignore_llm_for_these_commands.md (top, mc, editors, and others) inherit the TTY in agent and root. Their output is not chat history.

Tool styles (:tools, ENGRAM_TOOL_STYLE): auto (native tool_calls, else text patterns), native, text. tiny defaults to text. Allow-listed text tools: shell_exec, read_file, write_file, list_dir, load_skill, plus mcp__ names.

    TOOL shell_exec command=apk add neovim

or a tool_call block:

    <tool_call>{"name":"list_dir","arguments":{"path":"/etc/engram"}}</tool_call>


LEARN

docs/learn.md
docs/adr/0008-learn-userland-verb.md
Agent mode only.

A line starting with a comma or ?? is intent, handled before direct-shell and LLM routing. The model returns visible shell as {command, rationale}. The user confirms [r]un, [e]dit, or [q]uit. After a successful run, [s]ave asks the model for a POSIX script, a man page, and a BATS test. One repair retry. If BATS fails, nothing is installed.

- Command      ~/bin/<name>
- Man page     ~/share/man/man1/<name>.1
- Test         ~/bin/tests/<name>.bats
- Completion   ~/bin/completions/<name>
- Registry     ~/bin/.learn/<name>.toml

shomsky publish <name> emits a local apk for /usr/local/bin and the system man page. There is no community registry. ENGRAM_LEARN_STUB=1 serves canned payloads for CI. ENGRAM_LEARN_AUTO=1 auto-confirms run and save.


SHOMAGENT

docs/shomagent.md
docs/adr/0007-shomagent-background-crew.md
shomagentd starts with the container. SKIP_SHOMAGENT=1 skips it. Create a member before ask, talk, or write.

- shomagent watch or spawn "<cmd>" --tell-me "..." supervises that process. Ring buffer, token-budget summary against the brief, novelty filter (same class suppressed for an hour).
- shomagent read <path> allows ask and talk over the file. write is rejected.
- shomagent readwrite <path> allows ask and talk, plus write <id> "<text>" (append) and write <id> --replace.
- shomagent dream [path] is a foreground generative journal (default dream.md). Seeds a bash/Python topic, appends ReAct beats; type a line to steer, quit to leave. Per-beat rain uses ENGRAM_MATRIX*.
- shomagent dream seed [path] waits for a user-written seed (end with . or Ctrl-D) before the first LLM beat.
- shomagent refine idea [path] is a foreground idea rewrite (default idea.md). Standing task; each pass loads and overwrites the file. Type a line to replace the task, quit to leave.
- pause, resume, and stop <id> are the process lifecycle. stop on a document detaches and keeps the file.

--persist writes ./shomagent_crew.d/<name>.toml. Findings interrupt between prompts via /run/shomagent/notify. :shomagent or :agents lists the roster. SHOMAGENT_STUB_LLM=1 is for CI without a model. The summarizer uses the same local OpenAI-compatible URL.


MCP

docs/mcp.md
docs/adr/0004-mcp-integration-steering.md

The image ships engram-cmdfreq. On start the shell prints: mcp: connected 'cmdfreq' (2 tools: record_command, top_commands). The LLM sees mcp__cmdfreq__record_command and mcp__cmdfreq__top_commands. Recording of real shell lines is automatic. :top and the completer read /engram/user/.command_freq.json directly. When the user asks for their most-used or top 10 commands, call mcp__cmdfreq__top_commands with {"limit":10}.

A new server is an in-image stdio binary plus a [[mcp_servers]] entry. Empty mcp_servers leaves the shell working.


MODELS AND SKILLS

docs/models.md
SHOMSKY_MODEL selects an alias in /etc/engram/models.toml (mistral default, qwen, deepseek, tiny, and the smaller aliases listed there). ./choose_llm.sh writes .env. First start needs network (Hugging Face, optional HF_TOKEN). After the volume has the GGUF, inference does not. CPU cold start can take minutes. ENGRAM_LLM_READY_TRIES defaults to 600. Prefer tiny and ENGRAM_TOOL_STYLE=text for smoke tests. SKIP_LLM and SKIP_MODEL_FETCH exist for suites that do not need inference.

docs/engram.md
Skills are markdown with YAML frontmatter: name, description, always_load.

- shell                              always_load true. BusyBox vocabulary.
- packages                           always_load true. apk add and apk del. Search when the binary name differs from the package. Ledger in .packages.json.
- learn                              on demand via load_skill.
- ignore_llm_for_these_commands      on demand. The shell also reads it as the TUI bypass list.

:menu or :m on a color TTY covers Modes, Learn, Packages, shomagent, Help, and System. Under shomagent: list agents, type a filename for readwrite / dream seed / refine idea, or pick an opened document for ask / talk. :help is the same map as text. Both stay available from the ready line.


IF YOU ARE CHANGING THE REPOSITORY

1. Read the Accepted ADRs for the boundary you are touching before writing code.
2. Keep the musl/CPU image buildable. Do not add a glibc-only dependency to the flagship path.
3. Keep tool execution and mode checks in the shell.
4. Cover non-LLM behavior in tests/cases/ or --self-test. Run: docker compose run --rm tests   or   ./tests/run.sh
5. Use: cargo test -p shomagent -p shomsky
6. Write an ADR when the change moves a cross-cutting boundary (sandbox, MCP transport, CI gates, license posture), adds or removes an integration, or would surprise someone who only read the code. Skip ADRs for routine bugfixes and doc clarifications that do not change a decision.
7. How-to docs stay detailed. ADRs stay short: Status, Date, Context, Decision, Consequences, optional Steering.
8. Do not commit weights, tokens, or .env.

Build: Docker 24+ with BuildKit. ./start-shomsky-linux-shell.sh or docker compose run --rm shomsky. Bare docker compose up lets Compose's helper menu steal the keyboard. First mistral.rs compile is long. CARGO_BUILD_JOBS=1 on small builders. See docs/build-and-publish.md.


IF YOU ARE THE MODEL INSIDE THE SHELL

You are the agent in Shomsky Linux, an Alpine container, talking to a person at the engram-shell prompt. BusyBox ash is the real shell. Prefer the tools over invented output.

- Stay in the current mode. Do not claim you switched to root or that you wrote the host outside the container.
- In agent mode, call only allow-listed tools. shell_exec runs ash. read_file, write_file, and list_dir touch the sandbox filesystem. load_skill pulls a manual from /engram/skills. MCP tools use the mcp__{server}__{tool} name.
- Shell-shaped lines are already executed by the shell. Do not re-issue them unless the user is asking you to.
- Lines starting with a comma or ?? are the learn loop. Do not fake that loop with shell_exec. The user types the prefix at the prompt.
- Install and remove software with apk in agent mode. If which fails, search with apk search before assuming the package name matches the binary. Alpine often provides python3 and not python. Successful apk add and apk del are recorded for :packages.
- For "top commands" or "most used," call mcp__cmdfreq__top_commands with {"limit":10}.
- In hallucination mode, act as a virtual shell. Do not attempt real tools. Nothing you say should imply a disk write occurred.
- In root mode you are not in the loop.
- TUI programs in the ignore list are not yours to capture.
- Keep plans visible. Learn plans are real shell the user can read before they run.
- :menu and :help are the user's map. Point there when they are lost, and follow the skill you were given when one is loaded.
